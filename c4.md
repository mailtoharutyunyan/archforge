You are a senior software architect and staff-level full-stack engineer.

Your task is to design and implement a **professional, production-quality architecture modeling platform inspired by C4-PlantUML and Structurizr**, but substantially more modern and capable.

Do NOT simply clone C4-PlantUML syntax or create a thin wrapper around PlantUML.

The goal is to build an **Architecture IDE / Architecture-as-Code platform** where software architecture is represented as a structured model and can be visualized, validated, versioned, analyzed, and later modified by AI agents.

## Product vision

Build a system with this conceptual architecture:

```text
                         ARCHITECTURE MODEL
                                │
          ┌─────────────────────┼─────────────────────┐
          ↓                     ↓                     ↓
      Visual Views         Architecture Rules      Documentation
          │                     │                     │
     ┌────┼────┐                │                ┌────┼────┐
     ↓    ↓    ↓                ↓                ↓    ↓    ↓
    C4  UML  Deployment     Validation          ADR  Docs  Export
          │                     │
          └──────────────┬──────┘
                         ↓
                  Architecture Graph
                         │
          ┌──────────────┼──────────────┐
          ↓              ↓              ↓
       Git Diff      Impact Analysis    AI
                                      Architect
```

The platform should eventually become an **AI-assisted Architecture Engineering environment**.

# 25. Design principles

Follow these principles:

1. Architecture model is the source of truth.
2. Rendering is a projection of the model.
3. DSL is human-readable and AI-readable.
4. Architecture should be Git-friendly.
5. IDs must be stable.
6. Layout must be independent from semantics.
7. Inferred architecture must be distinguishable from declared architecture.
8. Validation must be deterministic.
9. AI changes must be reviewable before application.
10. Keep the core extensible.

---

# 26. What NOT to do

Do NOT:

* make a simple PlantUML wrapper
* hardcode diagrams
* store only SVGs
* make React Flow state the architecture source of truth
* put all architecture data into one huge JSON document
* tightly couple domain logic to rendering
* hardcode AWS diagrams into the core engine
* build fake AI functionality
* generate a giant monolithic backend
* skip tests
* skip validation
* create an MVP that only looks good but has no solid domain model
